# Core rules (loaded because you are in the domain layer)

Nothing new here — this is `CLAUDE.md` and `CODE_RULES.md` placed where the code
is. If it contradicts either of those, they win and this file is stale.

## The two layers never import each other

```
football layer (FPL, public)      →  the real Premier League
league layer  (Fantrax, cookie)   →  our fantasy competition
        ↘ join on player identity ↙
```

`packages/core/src/football/**` may not import from `league/`, and `league/**`
may not import from `football/`. A script does the wiring.

**Why, precisely: FPL's rules are fixed for everyone, and custom rules are what
Fantrax sells.** So the football layer may hold constants. The league layer may
not — roster limits, the position vocabulary, the scoring system, the period
calendar, the lineup deadline, team count, the schedule, the draft type are all
**data read from `getLeagueInfo`**. Never assumed, never inferred from FPL.

The corollary bites often: **when an FPL concept crosses into league territory it
arrives wearing football clothes.** `element_type` did, which is why position
left the football layer. `deadline_time` is the same mistake waiting to happen —
FPL's deadline is FPL's house rule and ours is a commissioner setting.

**The calendar is the one exception, and it crosses as plain data.**
`league/calendar.ts` declares its own `GameweekKickoff` rather than importing
`Fixture`. Being told a date is not importing an adapter.

## `raw.ts` mirrors reality, including its inconsistencies

Every Fantrax field is optional, and not because the API is flaky: **field
presence varies between leagues, not only between states.** On one day the real
league's `getLeagueInfo` carried `draftType` and `leagueHistoryId` and the
rehearsal league's carried neither. Domain types are ours and clean; the mapper
is the only place the two meet.

No `any`, no non-null `!`, no unchecked cast on provider data. Model absence as
`unmapped`/`unknown`, never as zero.

## Purity at the core

No clocks, no network, no randomness, no environment reads inside mappers,
scoring, gazette section builders or competition engines. Inject `fetchedAt` and
`now`. If a test needs a mock to reach pure logic, the logic is in the wrong file.

Nothing Next.js-specific lives in `packages/core`.

## Identity persists on `code`, never `id`

FPL's player `code` is season-stable and portraits key off it. FPL's `id` is
per-season and **must never be written to disk or into a mapping file**. Mappings
are generated by an auditable script and checked in as data. Never name-match at
runtime.
